<why>
One D700 reads 204-206 GB/s with a plain streaming kernel (16-byte loads, grid stride). Decode on the same card moves model bytes at only 37-52 GB/s (Qwen3-0.6B Q8_0 to Qwen3-8B Q4_K_M), and decode is mat-vec bound, so the mat-vec kernels, not the card, set the decode rate. The fork has 64-lane mat-vec kernels in ggml/src/ggml-metal/kernels/mul_mv_w64.metal (Q4_K at about line 1209: kernel_mul_mv_q4_K_f32_w64_impl<N_R0_Q4_K>; rows per simdgroup nr0, simdgroups per threadgroup via function constant FC_mul_mv_nsg), selected in ggml/src/ggml-metal/ggml-metal-device.cpp (ggml_metal_library_get_pipeline_mul_mv and the "_w64" naming around line 216; Q6_K/Q8_0 have "ext" w64 kernels around line 960).
